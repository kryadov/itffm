# Живность: зайцы, белки, змеи, пчёлы, стрекозы

Брейншторм 2026-09-10. Реализует пункт TODO.md «Живность помимо птиц».

## Зачем

`world/birds.ts` — единственная фауна в игре. TODO прямо предостерегает от
пяти параллельных ad hoc систем для оставшихся видов, поэтому архитектура
решается один раз, для всех видов сразу.

## Архитектура: два яруса, не один

Наземная и летающая живность физически ведут себя слишком по-разному для
одной state machine (полёт вокруг опорной точки — не «блуждание по земле» с
частным случаем). Решение — два лёгких модуля с общим низкоуровневым
инструментарием (`findOpenSpot`, `TreePerch`, `classifyWater`), но раздельной
оркестрацией:

- **`world/critters.ts`** — заяц, белка, змея. Общая state machine:
  `idle → alert → flee → resting → idle`. Испуг от приближения игрока,
  как у птиц (`FLUSH_RADIUS`), но без взлёта/посадки — только движение по
  земле (или, для белки, вверх по стволу).
- **`world/insects.ts`** — пчёлы, стрекозы. Рой из нескольких особей,
  кружащих вокруг опорной точки (улей / пятно над водой) по орбите с шумом,
  без состояний «испуг»/«отдых» — они не реагируют на игрока, это фон.

Обе фабрики возвращают тот же тонкий контракт, что и `Birds`:
`{ update(dt, playerX, playerZ), setEnabled(on), dispose() }`.

## `world/critters.ts`

### Общая модель

```ts
export type CritterState = 'idle' | 'alert' | 'flee' | 'resting'

export interface CritterSpecies {
  key: 'hare' | 'squirrel' | 'snake'
  count: number
  fleeRadius: number     // player distance that triggers alert→flee
  alertDur: number        // seconds spent frozen in `alert` before fleeing
  fleeSpeed: number        // m/s while fleeing
  restMin: number
  restMax: number          // seconds resting before the next idle cycle
  climbsTrees: boolean     // squirrel: flee target may be a TreePerch
  buildGeometry(mat: THREE.Material, n: number): CritterMeshes
  poseIdle / poseFlee(...): void   // per-instance matrix composition
}
```

Один общий цикл обновления (позиция — чистая функция `state` + `stateT`, как
у `birds.ts`) читает `CritterSpecies` и крутит `n` особей через
`InstancedMesh`. Каждый вид — не файл со своей машиной состояний, а
конфиг + геометрия + функция позы, зарегистрированные в `critters.ts`.

### Сайтинг

`homeSpots: {x, z, y}[]` передаётся фабрике извне — вызывающая сторона
(`scene.ts`) решает, где вообще может жить этот вид:

- Заяц, змея — `findOpenSpot` россыпью по поляне/подстилке (как
  существующие `bushObstacle`-подобные россыпи), не в стволах деревьев.
- Белка — `treePerches(trees)` (уже есть, `trees.ts`), та же коллекция, что
  использует `birds.ts`.

### Испуг

`idle`/`resting` → как только игрок ближе `fleeRadius` (или таймер
`resting` истёк) — `alert` на `alertDur` секунд (застыл, замер), затем
`flee`: заяц/белка — быстро прочь от игрока (белка — к ближайшему
`TreePerch`, если `climbsTrees`), змея — тем же переходом, но с низкой
`fleeSpeed` и меньшим `fleeRadius` («медленно уползает» вместо испуга
вскачь — решено в брейншторме). По истечении дистанции/времени —
`resting` на точке остановки, затем обратно в `idle`.

### Геометрия

Низкополигональные instanced-меши в духе `birds.ts` (октаэдр-тело, конус/
призма-детали), не детальные модели — та же причина: сотни существ,
draw-call бюджет. Заяц — вытянутое тело + уши-конусы; белка — тело +
пушистый треугольный хвост, поднятый дугой; змея — цепочка сегментов вдоль
кривой (несколько instanced-цилиндров/сфер на сегмент, поза считается по
кривой пути, не по костям).

### Настройки

Ничего нового: как у птиц — `setEnabled` управляется тем же общим
переключателем производительности/погоды, если он появится, но отдельного
UI-тоггла для живности TODO не просит.

## `world/insects.ts`

### Общая модель

```ts
export interface SwarmSpecies {
  key: 'bee' | 'dragonfly'
  count: number
  orbitRadius: number
  orbitSpeed: number
  bobAmplitude: number
  buildGeometry(mat: THREE.Material, n: number): SwarmMeshes
}
export function createSwarm(scene, rand, species: SwarmSpecies, anchors: {x,y,z}[]): Swarm
```

Каждая особь получает фиксированный (детерминированный) фазовый сдвиг и
кружит вокруг ближайшего к ней `anchor` по эллиптической орбите с лёгким
вертикальным дребезгом (`Math.sin`), без состояний — чистая функция
времени, как перья/дым. `anchors` — точки, откуда рой не отходит:

- Пчёлы — точка(и) улья (одна на лес, см. ниже).
- Стрекозы — несколько точек над водой (пруд/тихий участок ручья), не над
  быстрой/узкой протокой сплошь.

### Улей

Новый объект `world/hive.ts` (по образцу `campfire.ts`/`fisherHut.ts`):
`placeHive(trees, obstacles, halfSize, seed): Hive | null` — сажает улей у
ствола случайного дерева в пределах разумного радиуса от центра, как дупло/
пень («дикий улей», решено в брейншторме), не как отдельно стоящий ящик.
Возвращает `{x, y, z, rotationY}`, привязанный к конкретному дереву.
`hiveObstacle` — небольшой круг коллизии (как у костра), чтобы игрок не
проходил сквозь ствол-с-ульем ближе, чем обычное дерево уже не пускает —
скорее всего избыточно, если улей сидит вплотную к стволу, который и так в
`treeCircles`; решается по месту при реализации, а не заранее.

### Стрекозы

Без нового объекта — сайтинг напрямую по `water: Vec2[][]`, выбираются
несколько точек вдоль контура пруда/тихой воды
(`classifyWater(ring) === 'pond'` или спокойный участок ручья), рой из
`SwarmSpecies` вокруг каждой.

## Интеграция в `game/scene.ts`

`Forest` получает:
- `updateCritters(dt): void`, `updateInsects(dt): void` — вызываются из
  `main.ts` рядом с `updateBirds`/`updateCampfire`.
- Ни зайцы/белки/змеи, ни пчёлы/стрекозы не входят в `extraObstacles` —
  живность не блокирует игрока физически (как птицы сегодня), только
  реагирует на его положение.
- Улей — да, лёгкий `hiveObstacle`, поскольку это физический объект у
  ствола (риск провалиться внутрь модели при отсутствии коллизии).

## Порядок реализации

Решено в брейншторме: сперва каркас `world/critters.ts` + заяц + белка
(проверяют каркас на деле — им хватает существующих `findOpenSpot`/
`treePerches`), затем змея (третье состояние поведения по месту), затем
`world/insects.ts` + улей + пчёлы, последними — стрекозы (зависят от воды,
которая не в каждой локации есть — как домик рыбака).

## Тестирование

TDD как везде в проекте: детерминированность (`rand()`-seed → тот же
результат), state-transition тесты на `critters.ts` (испуг срабатывает на
дистанции, `resting` не бесконечен), сайтинг (белка находит `TreePerch`,
заяц/змея — открытое место, улей садится у дерева, стрекозы — только когда
есть вода и вблизи пруда, не быстрой протоки). Визуальная проверка —
headless-скриншот хотя бы одного вида на каждый ярус (наземный + летающий),
как это делалось для шалаша/костра/домика рыбака.
